APK PROMPT 7D — FIX THE MOBILE BOOTSTRAP 500 ERROR

TASK

Diagnose and fix the production mobile-bootstrap endpoint that returns HTTP 500 for an unauthenticated request instead of the expected HTTP 401 JSON response.

REPOSITORY

Work only in:

shriqrdotcom/exzibo-mag

Do not modify the App-Manager-07 mobile repository.

Affected endpoint:

```text
GET https://dashboard.exzibo.online/api/mobile/v1/bootstrap
```

Current response:

```text
HTTP 500
Content-Type: application/json
{"error":{"code":"500","message":"A server error has occurred"}}
```

Required unauthenticated response:

```text
HTTP 401
Content-Type: application/json
Cache-Control: no-store
```

1. SAFETY CHECK

Before changing anything:

* Fetch and prune origin.
* Confirm this is the `exzibo-mag` repository.
* Confirm the tracked working tree is clean.
* Confirm the latest `origin/main` commit.
* Confirm the production Vercel deployment commit if read-only deployment metadata is available.
* Make three safe unauthenticated GET requests to the endpoint to confirm the failure is reproducible.
* Do not print cookies, tokens, environment values, database URLs, user data, or Vercel secrets.

If the endpoint has already recovered and consistently returns the correct 401 response, do not create a branch or dummy commit. Report the recovery and verification results.

2. DIAGNOSE THE ROOT CAUSE

Inspect only the relevant implementation:

* Mobile bootstrap route and Vercel route mapping
* Better Auth server configuration
* Server-side session lookup
* Authentication helpers
* Database/session adapter used by the route
* Error-handling and logging code
* Production environment validation
* Existing bootstrap and authentication tests

Use read-only Vercel logs if authenticated access is available. Redact request IDs, user data and secret values.

Determine whether the 500 is caused by:

* A route or import failure
* Better Auth session lookup
* Database connection failure
* Missing production environment-variable name
* Incorrect production deployment
* Expired or incompatible database schema
* Exception handling before the unauthenticated response
* Another confirmed cause

Do not hide infrastructure failures by converting every exception into a 401.

Only a genuinely missing, invalid or expired session should return 401. Database, configuration and authentication-service outages must remain sanitized 500 responses and be logged server-side.

3. IMPLEMENT THE MINIMUM SAFE FIX

If the cause is a code defect:

* Create a branch from the latest `origin/main`:

```text
fix/mobile-bootstrap-unauthenticated-500
```

* Make the smallest necessary change.
* Preserve the authenticated bootstrap response and restaurant-membership checks.
* Preserve `Cache-Control: no-store`.
* Return a stable sanitized 401 JSON response for missing or invalid sessions.
* Do not expose internal errors, database details, stack traces or personal data.
* Keep real infrastructure failures as sanitized 500 responses with safe server-side logging.
* Do not weaken authentication or tenant isolation.

If the cause is a missing or incorrect Vercel environment variable, stale deployment or external configuration:

* Do not create an unrelated code commit.
* Report the exact variable name or deployment mismatch without printing its value.
* Do not change production environment variables or trigger a deployment unless already explicitly authorized.

4. TESTING

Add or update focused tests using the existing test framework for:

* Request without a session returns 401 JSON
* Invalid session returns 401
* Expired session returns 401
* Valid authenticated session still returns the correct bootstrap response

Run:

* TypeScript

Do not use a real customer session or modify production restaurant data.

If a code fix is required, verify locally or in the available test environment that the signed-out response is 401.

Push the clean branch for review and allow the normal GitHub PR and Vercel production process to handle deployment after merge.
