TASKS
==================================================

1. Inventory existing helper patterns in api/_lib.

2. Create safe error helper.

Error shape:

{
  ok: false,
  code: "STABLE_CODE",
  message: "Safe public message",
  requestId: "..."
}

Allowed codes:

BAD_REQUEST
UNAUTHORIZED
FORBIDDEN
NOT_FOUND
METHOD_NOT_ALLOWED
CONFLICT
RATE_LIMITED
PROTECTION_UNAVAILABLE
INTERNAL_ERROR

Unknown errors must return:

status 500
code INTERNAL_ERROR
message Internal server error

Never expose:

- err.message unless explicitly safe
- SQL text
- stack trace
- file paths
- cookies
- tokens
- secrets
- provider errors

3. Create request ID helper.

Rules:

- generate crypto.randomUUID() when missing
- accept x-request-id only if safe
- reject/replace oversized values
- reject/replace spaces, newlines, and control characters
- add X-Request-ID response header
- include requestId in error envelope
- never use requestId for auth

4. Create method allowlist helper.

Rules:

- unsupported method returns 405
- use safe error envelope
- set Allow header where practical
- OPTIONS must not run business logic

5. Create body/parser helper.

Rules:

- enforce explicit JSON body size limit
- oversized body returns safe error
- malformed JSON returns safe 400
- do not affect upload/media-specific limits

6. Create basic security headers helper.

Apply where called:

- X-Content-Type-Options: nosniff
- Referrer-Policy
- Permissions-Policy
- frame protection header where safe
- Cache-Control for private API responses

Do not add CSP here.

==================================================
TESTS REQUIRED
==================================================

Add focused tests proving:

1. Missing request ID generates one.
2. Valid x-request-id is preserved.
3. Oversized request ID is replaced/rejected safely.
4. Control-character request ID is replaced/rejected safely.
5. Error envelope includes requestId.
6. Unknown exception returns INTERNAL_ERROR.
7. SQL-like error text is not returned.
8. Stack trace is not returned.
9. Secret-like value is not returned.
10. Known safe domain error keeps stable status/code.
11. Unsupported method returns 405.
12. Allow header is present where practical.
13. OPTIONS does not execute business logic.
14. Oversized JSON body is rejected safely.
15. Normal JSON body passes.
16. Malformed JSON returns safe 400.
17. Security headers are applied.
18. Headers do not expose secrets.
