5. IMPLEMENT SAFE LOGGING
==================================================

Use one consistent interface, for example:

securityLogger.info(...)
securityLogger.warn(...)
securityLogger.error(...)

or:

logSecurityEvent({
  event,
  severity,
  outcome,
  requestId,
  ...
})

Requirements:

- JSON output;
- stable event names;
- no secret leakage;
- errors sanitized;
- event logging must never break the request;
- logging failure must not expose internals;
- request ID included when available;
- tenant identity included only when authoritative;
- actor identity derived from server-side session;
- no client-provided role trusted;
- no logging of raw headers;
- no duplicate events for the same action unless intentional;
- no fire-and-forget promise rejection.

If asynchronous logging is used:

- catch all failures;
- do not delay critical requests excessively;
- do not lose security events silently when avoidable.
